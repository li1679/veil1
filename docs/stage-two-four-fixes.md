# 第二至第四阶段实施记录

## 第二阶段：性能

- 收件箱轮询改为完成后再排下一次请求：默认5秒，有变化保持5秒，无变化逐步退避到30秒，错误按重试时间和退避重试。
- 页面隐藏、切换邮箱、关闭页面或切换历史记录时取消旧请求；响应会校验邮箱地址和请求代次，旧邮箱响应不能覆盖当前收件箱。
- 收件箱请求去重，手动刷新与定时刷新不会重叠；内容签名未变化时不重新渲染邮件列表。
- 用户列表从默认逐用户加载邮箱改为只返回邮箱计数；展开用户时按需请求邮箱列表。用户列表新增分页，用户筛选使用轻量选项接口。
- 后端缓存改为按 D1 数据库对象隔离，拥有并发未命中合并、LRU 上限和失效期间不回填旧结果的保护。邮箱 ID、配额和统计 TTL 分别收紧为60秒、15秒、30秒。
- 配额读取合并为单条查询；绑定邮箱时使用数据库条件插入检查配额，降低并发超配额窗口。
- Service Worker 不再维护完整 JS 清单，改为静态资源按需 Network First 缓存；API 和 HTML 导航保持网络请求。缓存版本更新为 `veil-static-v4`。

## 第三阶段：公共模块和异步契约

- 新增 `async-actions.js`，统一防重复提交、按钮忙状态、有限并发批处理和进度反馈。
- API 错误统一为 `ApiError`，保留 HTTP 状态和 `Retry-After`；请求增加读写超时，超时提示不会伪装成成功。
- 复制操作只有实际复制成功才显示成功提示；失败时保留明确恢复提示。
- 确认框等待异步删除、批量操作和分配操作完成后才关闭，处理中禁止重复确认。
- 批量用户和邮箱删除按成功/失败逐项处理，失败项保留在列表和选择状态，不再把部分成功报告为全部成功。
- 邮件详情、管理员邮箱查看器使用同一邮件渲染器、验证码复制和取消请求逻辑。
- 发件权限改为实时查询，不使用可能滞后的授权缓存。
- 统一认证页、普通用户页、管理员页和邮箱用户页的共享弹层，删除三套重复的发件、邮件详情和确认框 HTML。
- 清理无调用的旧域名下拉菜单、历史分页上限常量、邮件正文缩放辅助逻辑和视觉补丁样式入口。

## 第四阶段：UI 和响应式

- 保留现有 iOS HIG、系统字体和单一 iOS 蓝色主题；统一间距、阴影、圆角和数据等宽数字 token。
- 提高浅色和深色模式下次要文字对比度，统一焦点环、选中态、禁用态、加载态、错误态和空态。
- 原生 `select` 替代自制域名下拉菜单，减少定位、键盘和触屏维护成本。
- 生成区在域名加载、配额耗尽、生成中和失败时显示明确状态；生成按钮按真实配额和域名状态禁用。
- 收件箱验证码直接作为操作按钮显示，减少悬停发现成本；邮件列表支持长地址换行和移动端紧凑布局。
- 用户管理和所有邮箱管理在平板保持可滚动表格，在手机切换为可展开记录；移除行高上限，避免邮箱列表被裁切。
- 弹层使用 `max-width`、`dvh`、安全区和正文横向滚动，邮件详情 iframe 使用 ResizeObserver 自适应高度。
- 移动端底部导航、批量操作栏、Toast、表单和表格均适配安全区与窄屏。
- 删除和批量操作采用短状态过渡，不再依赖大范围 `!important` 和重复的视觉补丁文件。
