# 第一阶段安全修复记录

## 范围

仅修改 `veil` 的安全相关后端及对应文档，未修改 UI，未读取或改动“副本，勿读勿动”。默认密码为邮箱地址的逻辑保持不变，包括登录校验、管理员查询、重置和自助改密的当前密码校验。

## 已完成

1. 输入验证：写接口校验 JSON 形状；保留批量发信数组及无请求体操作。自定义邮箱前缀拒绝首尾点号、连续点号和非字符串；域名必须来自配置列表。生成长度4-32，批量数量按角色50/100限制；拒绝小数、越界值及字符串布尔值。公开批量创建校验数量1-20、天数1-30、批量前缀58位上限。
2. 密码验证：不把对象、数组或数字自动转为密码。新设自定义密码6-128位，登录/校验现有密码最多1024位；保留首尾空格，不收紧默认密码规则。用户配额为0不再错误回退为10。
3. JWT：缓存有效期不超过令牌 `exp`，并绑定实际签名密钥，关闭密钥时不命中旧缓存。验证 HS256/typ/整数过期时间；UTF-8 编码签发支持非 ASCII 用户名。
4. 会话状态：已删除、改名、停用用户不能继续使用旧 Cookie；邮箱登录及后续 API 请求检查邮箱存在、未过期且允许登录。会话查询的数据库错误不再返回伪成功。
5. 滑动续期：24小时 Cookie 在剩余不超过6小时时，成功 API 响应换发 Cookie；过期会话不恢复，Root Token 不转换为 Cookie。保持 HttpOnly、SameSite=Strict 和 HTTPS Secure，登录/会话/续期响应不缓存。
6. 数据一致性：新增4个幂等触发器和 `r2_delete_queue` 表。邮箱创建者在插入/更新时必须存在；删用户将保留邮箱的创建者及发件记录用户引用置空。通过触发器实现可空引用约束，不重建现有表。
7. 用户删除：在 D1 batch 内重新检查共享关系，保留其他用户共享的邮箱；不再按请求前快照构造大批 IN 参数。TTL 删除改为事务批次并失效相关缓存。
8. R2 清理：所有消息删除路径在同一数据库事务中记录原件引用。Cron 分批删除原件，成功后移除队列项；失败不丢引用，下次重试。移除旧的 `ttlR2Cleanup.js`，统一清理逻辑。批量发信所有权查询分批，单次最多100个绑定参数。
9. 初始化：数据库初始化按数据库对象合并并发；fetch/email/scheduled 共用初始化结果，移除 fetch 层重复缓存，确保新约束在不同入口都安装。

## 运行与部署边界

- 本机未发现 Wrangler；未构建/部署 Worker，也未操作远端 D1、R2 或真实会话。静态检查不等于 Cloudflare 运行验证。
- Worker 在首次初始化时幂等安装新表和触发器，不重建旧表；上线前需确认实际 D1 支持与执行结果。手动初始化脚本同步包含新增结构。
- R2 原件删除是最终一致，不是 D1/R2 跨服务原子删除；默认等待下次每6小时 Cron。失败会保留队列且记入清理错误。
- 本轮不自动修复历史悬空引用，也不扫描已经失去消息引用的旧 R2 孤儿对象或“原件写入成功、入库失败”的对象。
- 本轮未增加 JWT 撤销表：退出登录清除当前浏览器 Cookie，但已泄露令牌不因此单独撤销；有效令牌访问可滑动续期。密码修改后的全端会话撤销未纳入此次改动。
- 输入现在拒绝原先被静默转换的非法值；外部脚本需遵守更新后的 `docs/api.md`。
